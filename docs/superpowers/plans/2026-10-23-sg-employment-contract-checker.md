# Singapore Employment Contract Checker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected Streamlit MVP where employees upload a PDF employment contract and (1) get a plain-English health check of its key terms, (2) chat about it, both grounded in one shared RAG pipeline over the Employment Act and MOM guidance.

**Architecture:** One `RagPipeline` holds a prebuilt FAISS index of official sources plus an in-memory index of the uploaded contract, and returns contract + official passages with citations. Use Case 1 = LLM term extraction → small rules engine → RAG-grounded LLM assessment per term. Use Case 2 = same retrieval → grounded answer. The LLM is not the legal source of truth: rule statuses can't be overridden, citations come only from retrieved passages, weak evidence becomes `Unable to Assess`.

**Tech Stack:** Python 3.11+, Streamlit (`AppTest`), PyMuPDF, faiss-cpu, Pydantic v2, OpenAI API (chat `gpt-4o-mini` overridable via `LLM_MODEL`; embeddings `text-embedding-3-small`; structured outputs via `client.chat.completions.parse`), pytest, `st.graphviz_chart`.

**Spec:** `/Users/edwinchen/workspace/ai-poc/Assignment.md`

## Global Constraints

- Streamlit Community Cloud (~1 GB RAM): no local embedding models or torch (embeddings via OpenAI); KB index prebuilt and committed; contract index built per session.
- Password protected (`APP_PASSWORD`). Secrets only via `src/config.get_secret` (env var, then local `.env`, then `st.secrets`); `OPENAI_API_KEY` required; secret values are never logged, printed, echoed in errors, committed, or pasted into chat (ADR 0012).
- Pages: Contract Health Check, Ask Your Contract, **About Us** (scope, objectives, data sources, features), **Methodology** (data flows, implementation details, **one flowchart per use case**).
- **Exactly three statuses**: `Consistent`, `Needs Attention`, `Unable to Assess`. A missing clause is a finding with one of these, never an automatic violation.
- Each finding shows: term, status, extracted wording (if any), plain-English explanation, reason, source + citation (if applicable), employer question (if appropriate).
- 11 terms: salary_payment, working_hours, overtime, annual_leave, sick_leave, probation, notice_period, deductions, termination, confidentiality, non_compete.
- PDF only, page references kept; invalid/empty/unreadable PDFs handled gracefully; PDFs over `MAX_PAGES = 40` are rejected with a friendly message (no truncation logic).
- Sources: Employment Act `https://sso.agc.gov.sg/Act/EmA1968`, `https://www.mom.gov.sg/employment-practices`, `https://www.mom.gov.sg/employment-practices/contract-of-service`. SSO returns 403 to automated fetch → save text manually. The two MOM pages are mostly navigation hubs → also fetch the substantive MOM sub-pages (hours/overtime, leave, termination, salary/deductions, key employment terms) with `scripts/fetch_mom.py` (T4a). The Act is supplied by the user as a saved SSO HTML page (`Employment Act 1968 - Singapore Statutes Online.html`, 154 sections, verified 2026-10-23) and converted to text by `scripts/act_html_to_text.py` (T4a).
- Never invent citations or fabricate findings on service failure. Distinguish statute vs MOM guidance vs contract wording.
- Privacy: don't log contract text; UI says contract text is sent to OpenAI; "Clear contract & results" button; README lists prototype limitations.
- Tests never call the network or the real OpenAI API (stubs/fakes); only **[manual]** steps do.
- Out of scope: contract comparison, accounts, agent workflows.

## Review Focus

- Scanned, corrupt or over-40-page PDF → friendly message, nothing sent to LLM (T2).
- Contract missing a term → finding with one of three statuses, no exception (T7, T8).
- Employee category/salary unknown → hours/overtime rule returns `Unable to Assess` (T6).
- LLM invents a citation or says `Consistent` without evidence → dropped / downgraded (T7).
- Malformed LLM output or API outage → friendly error, no fabricated findings (T6, T7).
- Prompt injection inside the contract → treated as data (T5).
- Question sources can't answer → refusal (T8).

## Shared types (`src/schemas.py`, Pydantic v2)

```python
Status = Literal["Consistent", "Needs Attention", "Unable to Assess"]
TERM_KEYS = [...11 keys above...]
class Page(BaseModel): number: int; text: str
class Passage(BaseModel): id: str; kind: Literal["law","guidance","contract"]; title: str; citation: str; url: str | None; page: int | None; text: str
class Hit(BaseModel): passage: Passage; score: float
class Evidence(BaseModel): contract: list[Hit]; official: list[Hit]
class Source(BaseModel): title: str; url: str; citation: str
class EmploymentContext(BaseModel): category: Literal["Workman","Non-workman","Manager or executive","Not sure"] = "Not sure"; monthly_basic_salary: float | None = None
class ExtractedTerm(BaseModel): key: str; found: bool; wording: str | None; page: int | None; weekly_hours: float | None; overtime_multiplier: float | None; annual_leave_days: float | None
class ContractTerms(BaseModel): is_employment_contract: bool; terms: list[ExtractedTerm]   # list, not dict: structured outputs disallow free keys; analyser keys by `key`
class TermAssessment(BaseModel): status: Status; explanation: str; reason: str; question: str | None; source_ids: list[str]
class RuleResult(BaseModel): term: str; status: Status; reason: str; source_ids: list[str]
class Finding(BaseModel): term: str; status: Status; wording: str | None; page: int | None; explanation: str; reason: str; sources: list[Source]; question: str | None
class Report(BaseModel): findings: list[Finding]; disclaimer: str
class QAResponse(BaseModel): answerable: bool; answer: str; cited_ids: list[str]   # LLM output for Q&A; code decides what is shown (ADR 0007)
class ChatTurn(BaseModel): role: Literal["user","assistant"]; content: str; evidence: Evidence | None = None
```

### Task 7: Contract analyser
**Files:** `src/contract_analyser.py`, `tests/test_contract_analyser.py`, sample PDFs (`clear_terms`, `missing_terms`, `ambiguous`, `heavy_deductions`, `varied_notice_leave`) via `make_samples.py`.
**Produces:**
